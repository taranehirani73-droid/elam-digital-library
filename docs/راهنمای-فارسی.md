# راهنمای کتابخانهٔ دیجیتال عیلام

این پروژه دو بخش مستقل دارد: برنامهٔ اندروید برای خواندن و یک ویرایشگر مرورگری برای مالک کتابخانه. رابط برنامه داخل APK است؛ فقط JSON، متن Markdown و تصویر از مخزن عمومی دانلود می‌شوند. هیچ توکن GitHub داخل برنامه یا ویرایشگر وجود ندارد.

## نرم‌افزارهای لازم

- Node.js نسخهٔ ۲۲ یا جدیدتر و npm؛ Git؛ برای ساخت اندروید JDK 17 و Android Studio همراه SDK 35 و Build Tools 35.0.0.
- این نسخه از Capacitor 6 استفاده می‌کند تا با JDK 17 کار کند. نسخه‌های وابستگی در package-lock.json ثبت شده‌اند.
- برای مطالعه و ویرایش محتوا Android Studio لازم نیست؛ برای تغییر کد اندروید یا ساخت APK لازم می‌شود.

در PowerShell داخل پوشهٔ پروژه:

```powershell
node --version
git --version
java -version
npm ci
npm run publish:content
npm run dev
```

نشانی نمایش‌داده‌شده در ترمینال را باز کنید. این نمایش مرورگری فقط برای توسعه است.

## اجرای OpenCode (اختیاری)

OpenCode برای اجرای برنامه لازم نیست. اگر می‌خواهید کد را با آن ویرایش کنید، مطابق راهنمای رسمی https://opencode.ai/docs/ آن را نصب کنید. در محیط پشتیبانی‌شده می‌توانید `npm install -g opencode-ai` و سپس داخل پوشهٔ پروژه `opencode` را اجرا کنید. پشتیبانی Windows و WSL را پیش از نصب در مستندات رسمی بررسی کنید. تنظیم حساب و ارائه‌دهندهٔ مدل داخل خود ابزار انجام می‌شود؛ کلیدها را در مخزن پروژه ذخیره نکنید.

## ساخت مخزن و اتصال GitHub

۱. در GitHub یک مخزن عمومی بسازید. فایل خصوصی یا کلید امضا را در آن قرار ندهید.
۲. این پوشه را با GitHub Desktop به مخزن متصل کنید؛ یا از دستورات زیر با نشانی واقعی مخزن خود استفاده کنید:

```powershell
git init
git branch -M main
git add .
git commit -m "Initialize Elam digital library"
git remote add origin https://github.com/OWNER/REPO.git
git push -u origin main
```

۳. در Settings > Pages، منبع انتشار را **GitHub Actions** انتخاب کنید.
۴. گردش `Validate and publish public content` را از Actions اجرا کنید. تا سبز شدن کامل آن صبر کنید.
۵. نشانی محتوا چنین است: `https://OWNER.github.io/REPO/content/`. آن را در «الإعدادات» برنامه وارد و «حفظ وتحديث» را بزنید.
۶. ویرایشگر در `https://OWNER.github.io/REPO/editor/` قرار می‌گیرد. این صفحه فقط فایل تولید می‌کند و دسترسی نوشتن به مخزن ندارد.

نشانی عمومی محتوای همین پروژه در `src/config.ts` به‌عنوان پیش‌فرض ثبت شده است و از تنظیمات برنامه قابل تغییر است. در نصب اولیه، محتوای همراه فوراً باز می‌شود و دریافت نسخهٔ عمومی در پس‌زمینه انجام می‌گیرد. GitHub Pages فقط محتوای عمومی و ویرایشگر را میزبانی می‌کند؛ رابط خواننده از اینترنت بارگیری نمی‌شود.

## افزودن یا ویرایش مطلب بدون کدنویسی

۱. برای اجرای محلی ویرایشگر `npm run editor` را بزنید؛ یا صفحهٔ ویرایشگر منتشرشده را باز کنید.
۲. آخرین نسخهٔ مخزن را با GitHub Desktop دریافت کنید. سپس پوشهٔ **content** را در ویرایشگر انتخاب کنید. برای هر نوبت ویرایش، ابتدا کل پوشه را وارد کنید تا مطالب قبلی حفظ شوند.
۳. «مادة جديدة» را بزنید یا مطلب موجود را انتخاب کنید. شناسه و slug را با حروف کوچک لاتین، رقم و خط تیره بنویسید؛ برای ویرایش مطلب موجود شناسه را تغییر ندهید.
۴. عنوان عربی، خلاصه، مؤلف، تاریخ، نوع، دسته‌ها، برچسب‌ها، متن و منابع را وارد کنید. سال یا صفحهٔ نامعلوم را خالی بگذارید؛ حدس نزنید.
۵. برای کتاب، نوع «كتاب» را انتخاب کنید. فقط نوشتهٔ مجاز خود یا خلاصه و معرفی مستند بنویسید؛ متن کامل کتاب دارای حق نشر را بدون مجوز بارگذاری نکنید.
۶. برای ویدئو، نوع «فيديو» و پیوند معتبر YouTube را وارد کنید. برنامه ویدئو را دانلود نمی‌کند؛ پیوند در مرورگر باز می‌شود.
۷. برای داستان، «قصة» و برچسب «رواية أدبية» انتخاب می‌شود؛ داستان تخیلی نباید «موثّق» ثبت شود.
۸. عکس JPG، PNG یا WebP تا ۵ مگابایت انتخاب کنید؛ نام فایل لاتین و یکتا باشد. نام عکاس، مجوز و منبع تصویر را هم وارد کنید. عکس‌های فعلی اطلاعات مجوز دارند.
۹. با «معاينة النص» پیش‌نمایش را ببینید؛ سپس «تحقق واحفظ المادة» را بزنید. این ذخیره موقت و در همان جلسه است؛ قبل از بستن صفحه حتماً ZIP بگیرید.

متن Markdown از تیتر، فهرست، نقل‌قول، جدول و پیوند HTTPS پشتیبانی می‌کند. HTML اجرایی، اسکریپت و iframe نمایش داده نمی‌شوند. عکس اصلی از فیلد غلاف وارد می‌شود؛ برای پایداری آفلاین، تصویر خارجی در متن Markdown نمایش داده نمی‌شود.

## دسته‌بندی جدید

در بخش «الأقسام» ویرایشگر، شناسه، نام، توضیح و مسیر عکس را وارد کنید. برای زیرگروه، والد را انتخاب کنید. دسته‌های در حال استفاده یا دارای فرزند حذف نمی‌شوند. هر مطلب می‌تواند چند دسته داشته باشد. شناسهٔ دستهٔ مورد استفاده را تغییر ندهید؛ ابتدا مطلب‌ها را به دستهٔ جدید منتقل کنید. ساختار دسته‌ها از JSON خوانده می‌شود و افزودن دسته به نصب مجدد نیاز ندارد.

## انتشار تغییرات

۱. «تنزيل حزمة المحتوى ZIP» را بزنید و ZIP را در پوشه‌ای جدا باز کنید.
۲. از content فعلی نسخهٔ پشتیبان بگیرید. فایل‌های content خروجی را روی content مخزن کپی کنید.
۳. با GitHub Desktop تغییرات را بررسی و commit و push کنید.
۴. GitHub Actions شناسه‌ها، فیلدها، دسته‌ها، مسیرها، متن‌ها و تصاویر را بررسی می‌کند. مسوده‌ها منتشر نمی‌شوند. اگر آزمون شکست بخورد، نسخهٔ قبلی Pages باقی می‌ماند.
۵. پس از موفقیت انتشار، برنامه را باز کنید یا «تحديث» را بزنید. تغییر محتوا به ساخت APK تازه نیاز ندارد.

## مطالعه، آفلاین و تنظیمات

نوار پایین شامل الرئيسية، الأقسام، المحفوظات و الإعدادات است. جست‌وجو عنوان، خلاصه، نویسنده، برچسب و نام دسته را بررسی می‌کند؛ اعراب و شکل‌های مختلف الف نادیده گرفته می‌شوند. نوع و دسته را فیلتر کنید و با تاریخ یا حروف الفبا مرتب کنید.

هر مطلب صفحهٔ جدا دارد؛ اندازهٔ خط، ظاهر روشن و تیره، نوار پیشرفت، ذخیرهٔ محلی و منابع در دسترس‌اند. «نسخ الرابط» پیوند `elamlibrary://read/ID` می‌سازد که روی دستگاه دارای برنامه باز می‌شود؛ گیرنده باید آن مطلب را در فهرست خود داشته باشد.

نسخهٔ کامل محتوا و تصاویر در یک تراکنش IndexedDB ذخیره می‌شود. قبل از جایگزینی، همهٔ فایل‌ها و SHA-256 بررسی می‌شوند. دانلود ناقص یا خراب نسخهٔ قبلی را پاک نمی‌کند. بدون اینترنت، آخرین نسخهٔ سالم نمایش داده می‌شود. پاک‌کردن داده‌های برنامه، کش و علاقه‌مندی‌ها را پاک می‌کند. در صورت کمبود فضای ذخیره، برنامه نسخهٔ قبلی را نگه می‌دارد و خطا نشان می‌دهد.

## ساخت و نصب APK

```powershell
npm ci
npm test
npm run android:sync
cd android
.\gradlew.bat assembleDebug
```

برای ساخت محلی باید `JAVA_HOME` به JDK 17 و `ANDROID_HOME` به SDK نصب‌شده اشاره کنند؛ یا مسیر SDK در `android/local.properties` ثبت شود. این فایل برای هر دستگاه متفاوت است و وارد Git نمی‌شود. خروجی معمول در `android/app/build/outputs/apk/debug/app-debug.apk` است.

راه آسان‌تر: گردش **Build Android APK** را در GitHub Actions دستی اجرا کنید و APK را از Artifacts دریافت کنید. این گردش برای تغییر کد برنامه است؛ برای تغییر متن و عکس لازم نیست.

APK را به گوشی منتقل کنید، اجازهٔ نصب از همان برنامهٔ فایل‌منیجر را بدهید و نصب کنید. بستهٔ debug برای آزمایش است. انتشار فروشگاهی به امضای release اختصاصی نیاز دارد؛ کلید خصوصی را وارد مخزن نکنید. ساخت موفق به معنی آزمون روی همهٔ گوشی‌ها نیست؛ پیش از توزیع نهایی روی دستگاه واقعی آزمون کنید.

## رفع خطاهای متداول

- **محتوا به‌روز نمی‌شود:** نشانی باید HTTPS و پایانش `/content/` باشد. انتشار Actions باید موفق شده باشد. نشانی صفحهٔ GitHub یا `github.com/...` جایگزین GitHub Pages نیست.
- **خطای اعتبارسنجی:** پیام Actions یا ویرایشگر را بخوانید؛ شناسهٔ تکراری، دستهٔ حذف‌شده، مسیر نادرست و متن خالی علت‌های رایج‌اند.
- **خطای CORS:** از نشانی عمومی Pages استفاده کنید، نه فایل خصوصی یا لینک raw دارای احراز هویت. هیچ توکنی وارد برنامه نکنید.
- **تصویر دیده نمی‌شود:** فایل باید در content/images باشد؛ حروف کوچک و بزرگ مسیر و نام فایل باید یکسان باشند. مسیر تصویر نسبی است.
- **تغییر قبلی ناپدید شد:** قبل از ویرایش آخرین content را وارد کنید؛ ذخیره در فرم بدون دانلود ZIP دائمی نیست.
- **ساخت اندروید شکست خورد:** JDK 17، SDK 35، Build Tools 35.0.0 و دسترسی به مخازن Google و Maven را بررسی کنید. کمبود فضای دیسک نیز می‌تواند مانع ساخت شود.
- **گوشی محتوا را آفلاین ندارد:** یک بار اجازه دهید دریافت کامل شود. در نصب اولیه، محتوای نمونه همراه برنامه است.

فایل `docs/ACCEPTANCE.md` وضعیت آزمون‌ها و محدودیت‌های واقعی این تحویل را ثبت می‌کند.
