# وضعیت تحویل و آزمون‌ها

تاریخ: ۳۱ اکتبر ۲۰۲۶.

| مورد | نتیجهٔ واقعی |
|---|---|
| React + Vite + TypeScript + Tailwind | ساخت production موفق؛ رابط محلی داخل APK |
| رابط عربی راست‌به‌چپ | در مرورگر مشاهده شد؛ جست‌وجو، خواندن و علاقه‌مندی آزموده شد |
| محتوای اولیه | ۱۶ مدخل، پنج عکس واقعی، ۱۰ دسته، منابع و حقوق تصاویر |
| Markdown و JSON مستقل | موجود و اعتبارسنجی‌شده |
| دستهٔ پویا و مطلب جدید بدون نصب مجدد | آزمون خودکار دریافت دادهٔ جدید موفق |
| IndexedDB و نگهداری نسخهٔ سالم | آزمون دریافت سالم، قطع اتصال، خرابی فایل و عدم جایگزینی موفق |
| جست‌وجو | آزمون نرمال‌سازی عربی، دسته، نوع و نتیجهٔ خالی موفق |
| ویرایشگر | ساخت دسته و داستان از فرم در مرورگر موفق؛ ZIP خروجی باز و JSON و Markdown آن بررسی شد |
| طبقه‌بندی داستان | داستان بدون برچسب «رواية أدبية» رد می‌شود |
| قالب‌ها و راهنمای فارسی | در templates و docs موجود |
| GitHub Pages و Actions | فایل گردش کامل آماده؛ اجرای واقعی روی حساب مالک هنوز تأیید نشده |
| حساب مقصد | taranehirani73-droid؛ مخزن پیشنهادی elam-digital-library؛ مخزن و Pages ساخته‌شده اعلام نمی‌شوند تا واقعاً تأیید شوند |
| APK سبک 1.0.0-light | ساخته و امضای v1/v2/v3 و همسانی هر ۲۸ دارایی بسته بررسی شد؛ React با پوستهٔ WebView محلی HTTPS، نه پوستهٔ Capacitor |
| پروژهٔ استاندارد Capacitor | در android موجود، sync موفق؛ ساخت محلی به محدودیت فضا و دریافت وابستگی‌ها برخورد کرده است؛ گردش ساخت GitHub Actions موجود |
| آزمون روی دستگاه یا شبیه‌ساز | انجام نشده؛ هیچ ادعای آزمون سخت‌افزاری وجود ندارد |

APK سبک، رابط و JSON و Markdown و تصاویر را از همان خروجی www بسته‌بندی می‌کند. تغییر آدرس محتوا از تنظیمات، بارگیری شبکه و کش آفلاین همان پیاده‌سازی React هستند. برای این پوسته، بازگشت و deep link به‌صورت بومی پیاده‌سازی شده‌اند. پروژهٔ Capacitor از افزونهٔ App برای foreground، back و deep link استفاده می‌کند.

شش آزمون خودکار با `npm test` اجرا شده‌اند. تطبیق SHA-256 فایل‌های داخل APK با خروجی ساخته‌شده به معنی اجرای برنامه روی گوشی نیست. عملکرد واقعی GitHub Pages فقط پس از ساخت مخزن، انتشار موفق و دریافت از نشانی عمومی قابل تأیید نهایی است.

نسخهٔ سبک با کلید آزمایشی محلی امضا شده است. خروجی debug در GitHub Actions ممکن است کلید متفاوت داشته باشد؛ برای ارتقا میان دو امضا باید ابتدا نسخهٔ قبلی حذف شود که دادهٔ محلی آن را پاک می‌کند. برای انتشار پایدار، یک کلید release اختصاصی و محفوظ به کار ببرید.
